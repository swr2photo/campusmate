# CampusMate SwiftUI places library

The Activities tab on iOS has a button that opens `/landmarks`. This screen embeds a real SwiftUI view through a local Expo module. It adapts the places, favorites, collections and optional Rust synchronization from the Landmarks project. The bundled catalog contains 21 world landmarks; it is separate from CampusMate's campus meeting spots and Firebase party data.

## Implementation

- `modules/campus-landmarks/ios/CampusLandmarksView.swift`: SwiftUI navigation, search, maps, favorites and collection editing. iOS 26 uses native glass; older supported iOS versions use system materials and controls.
- `CampusLandmarksModule.swift`: `ExpoUIView` registration and availability query.
- `CampusLandmarksStore.swift`: local library and revision-based sync. Archives, recovery copies and Keychain sessions are scoped by a SHA-256 digest of the current CampusMate user identifier. This is local separation, not authentication to the Rust service.
- `LandmarksAPI.swift`: Rust JSON contract, HTTPS validation, redirect rejection and ephemeral HTTP session.
- `src/CampusLandmarksView.ios.tsx`: typed props, native event callbacks, Expo modifier event forwarding and `Host`.
- The base component renders an unavailable state on Android/web. An older iOS binary or Expo Go can also show this state until rebuilt with the module.

Props include `title`, `storageScope`, `backendURL`, `syncEnabled` and Expo UI `modifiers`. Callbacks are `onClose`, `onSelectPlace` and `onLibraryChange`. Native callbacks are explicitly dispatched in Swift and normalized to typed payloads by the TypeScript wrapper.

The catalog text is derived from Apple's sample and retains `APPLE-SAMPLE-LICENSE.txt`. No sample photographs are included; maps and SF Symbols supply the visual content. This avoids depending on generated string-catalog symbols or main-bundle image assets from the standalone sample.

## Build on macOS

Use the repository's pnpm dependency setup and Xcode appropriate for Expo SDK 58. Rebuild after adding or changing Swift files:

```sh
pnpm install --frozen-lockfile
npx expo prebuild --platform ios --no-install
npx expo run:ios
```

Native code cannot be delivered by a JavaScript-only update. Do not treat Metro export as an Xcode build. The module preserves the host app's iOS minimum (16.4) and guards iOS 26 glass APIs.

## Optional Rust sync

Offline use needs no server. Enable sync in the native screen's settings and supply a base HTTPS URL, or configure `EXPO_PUBLIC_LANDMARKS_API_URL` before bundling. A URL is public configuration; never put a bearer token in that variable. Sessions are generated by the service and stored in the device Keychain.

The existing Rust service lives at `C:\Users\This PC\Downloads\LandmarksBuildingAnAppWithLiquidGlass\backend`. From its project root on Windows:

```powershell
.\scripts\Start-Backend.ps1
```

Debug builds accept `http://localhost:8080` for an iOS simulator running beside the server. A physical phone cannot reach a Windows server using the phone's own `localhost`; use a reachable HTTPS endpoint. Release builds always require HTTPS. No production endpoint is deployed by this change.

Sync uses anonymous per-install sessions. Signing into the same CampusMate account on another device does not restore this library. Firebase authentication is not transmitted to the Rust service. Replacing a local library after a conflict requires confirmation and creates a local recovery copy first.

## Validation

The accompanying `landmarks-expo-validation.md` records checks performed on Windows and the native checks still required on macOS. Before release, verify opening/closing the route, search, favorites, collection create/edit/delete, large text, VoiceOver, switching CampusMate accounts, offline relaunch, real Rust sync, and conflict resolution on an iOS simulator/device.
